# PPT 制作与交付

## 一、交接契约

开始制作前具备：

1. `需求调研.md`：核心必填项齐全，制作路线与输出格式无冲突。
2. `PPT详细大纲_确认版.md`（入口①②）或 `修改方案_确认版.md`（入口③）：包含完整逐页内容/修改清单，以及有效确认依据（快速模式下为授权依据）。
3. 事实、图表数据与必需图片已就绪，或用户已经同意具体的删改与替代。
4. 已解析的制作 Skill 绝对路径、deck/模板根路径、制作工作区目录和最终成品路径；`doctor.py` 对选中分支的检查已通过（或已记录缺失项与用户决定）。
5. HTML 已根据视觉风格选定路径；guizang 的 A/B、主题和正式演讲时间预算已确定。
6. 以上 A 类文档均已先在前台展示，获用户确认后落盘；不能把后台生成的文档当作已完成前台确认。快速模式的依据见 [confirmation.md](confirmation.md)「快速模式」。
7. 入口③：源 PPTX 已有只读副本，修改方式、范围、必须保留项和 `修改方案_确认版.md` 已确认；未改动页已列明，或已说明 Beautify 全量重设计的保留规则。

依赖预检和复检按 SKILL.md §四「依赖预检与解析」执行，结果记入 `需求调研.md`。`{skill:<id>}` 表示解析出的依赖根目录，正文不写死路径。目标工作区取本次任务实际读写的工作区根目录（即 `projects/` 所在目录）；不确定时向用户确认。

调用是加载并执行选中制作 Skill 的 `SKILL.md`，不默认启动子代理或另建聊天：

- **同会话执行（默认）**：把下方清单作为内部交接核对项逐条对齐，**不在对话中向用户打印这段文字**。
- **子代理执行（仅在需要隔离上下文而启动子代理时）**：把下方清单替换为实际值后，连同下方“制作与交接约束”一起作为子代理的任务描述发送。

```text
需求文件：{绝对路径}/需求调研.md
完整确认大纲/修改方案：{PPT详细大纲_确认版.md 或 修改方案_确认版.md 的绝对路径}
目标、听众、场景、时长：{需求值}
制作路线：{套公司模板 / 用现成设计模板 / 从零设计}
视觉密度：{复杂豪华 / 专业简洁}
视觉风格、主题及颜色：{用户原始要求；guizang 的 A/B 与主题；html-ppt 已确认的默认主题或所选主题}
具体场景：{需求值 / 未提供}
演示语言：{中文 / 英文 / 中英双语 / 其他}
画布比例：{16:9 / 4:3 / 其他}
路由依据：{用户的制作路线、输出格式、具体场景或 HTML 风格要求，见 SKILL.md §四}
时间预算：{逐页讲述合计、互动/问答、缓冲、总时长及问答口径}
输出格式：{可编辑 PPTX / HTML / PPTX + HTML 双格式}
确认方式：{逐阶段确认 / 合并确认 / 授权直出：用户原话}
制作 Skill 根目录：{已验证的绝对路径}
依赖来源与版本：{解析 source、version；缺失项 / 无}
模板：{deck 名称与根目录 / 用户 `.pptx` 模板文件 / 由其导入的 deck / gorden 内置模板名 / 不适用（从零设计） / HTML 风格 / 源 PPT 原生设计}
gorden 模式（仅分支 C）：{A 内置模板 / C 原创简洁 / 不适用}
项目目录：{绝对路径}
制作工作区：{绝对路径，默认 {项目目录}/_build/<skill 名>/}
最终成品路径：{项目根目录下的标准路径 `{项目目录}/{项目目录名}.pptx/.html`；若用户额外指定输出路径/文件名则一并列出}
源 PPTX / 修改方案 / 修改方式 / 必须保留（仅入口③）：{对应值 / 不适用}
```

制作与交接约束：
- 只加载选中依赖的 `SKILL.md` 及其要求的文档；不把依赖内容复制进项目，也不修改依赖安装文件；依赖更新一律先经用户同意。
- 入口①②采用确认稿的完整内容、页序和页数，保留全部结论、数据和必要说明；文字压缩和视觉编排以可读性为准，文本与约定图表/表格必须可编辑。
- 入口③按修改方案执行：未列入清单的页面、文字、数据、品牌元素和页序保持原样，不得覆盖源文件。
- 中间产物保存在 `_build/<skill 名>/`（ppt-master 用其项目初始化的基础目录参数建在该工作区内，不在项目根目录直接初始化）；构建完成后将最终成品复制为项目根目录下的标准路径（以及用户额外指定的输出路径），`exports/`、`validation/` 留在工作区作检查证据。
- 已经明确的需求直接复用，不重新完整调研；制作 Skill 另有确实未回答的设计问题或必要确认时，只问剩余部分。
大纲确认不能冒充后续设计方案的确认，也不自动授权跳过所选 Skill 的阻塞检查。
不要把“已有完整确认大纲”理解成“用户要求 Quick”或“跳过策略”的指令。本编排层的快速模式也不等于下游 Skill 的 Quick 模式；授权直出时，下游的设计偏好询问由 AI 按已记录的决定作答，阻塞检查照常执行（范围见 confirmation.md「快速模式」）。
下游模板不能承载已确认的页数、数据或必要图示时，说明具体差异并回到策划确认，不默默删页、删数据或替换制作路线。
下游会自动写 Markdown 的命令：写 A 类文档前按规则展示确认；只写引擎内部产物时可直接执行并在阶段结束汇报。无法区分时先说明限制并等用户决定。

## 二、分支规则

### A. 套公司模板：ppt-master

- Skill：`{skill:ppt-master}/SKILL.md`。
- deck 根：`{skill:ppt-master}/templates/decks/`。deck 选择、模板来源和品牌归属按 SKILL.md §四「公司模板」；没有可用 deck 时给出安装 fork 或补齐 deck 的指引。
- 传入完整 deck 工作区根目录，不能只传内部 `templates/`，也不能把 `exports/` 中的预览 PPTX 当成唯一制作源。
- 所选 deck 需包含 `templates/design_spec.md`、页面 SVG 与 `images/` 资源，且已登记在 `decks_index.json`。
- 准确路由和前置检查以 ppt-master 当前入口及 `workflows/routing.md` 为准。
- 按其要求执行，不在本 Skill 中复制底层命令。
- 封面、目录、章节、正文和结束页遵循品牌规范；视觉密度只能在品牌允许范围内体现层次和信息密度。
- 不修改用户的原始模板。
- 输出固定为 `{项目目录}/{项目目录名}.pptx`，不提供 HTML 选择。ppt-master 只导出到其工作区的 `exports/<项目名>_<时间戳>.pptx`，完成后复制为上面的成品路径。

### B. 从零设计 + 可编辑 PPTX：ppt-master 自由设计

- Skill：`{skill:ppt-master}/SKILL.md`，Generate PPTX / free_design。
- 不加载任何公司 deck，不把 HTML 分支的固定配色扩展为该分支的硬限制。
- 用户明确选 B 时，视觉密度默认专业简洁：清晰主张、适量信息、克制配色与留白，必要的架构和流程关系仍应完整；用户要求复杂豪华时增加图示和信息组织，但保持可编辑与可读性。
- 输出为 `{项目目录}/{项目目录名}.pptx`，同样从 ppt-master 的 `exports/` 复制得到。

### C. 用现成设计模板（gorden 内置模板库）+ 可编辑 PPTX：gorden-ppt-skill

- Skill：`{skill:gorden-ppt-skill}/SKILL.md`。
- 触发、候选、许可、能力边界和模式选择按 SKILL.md §四。模板承载不了额外要求时，先换模板或换页；仍不行才说明具体差异，请用户决定。
- **更新（有意覆盖其入口要求）**：gorden 要求每次先跑 `scripts/apply_update.py`，这会改写已锁定的安装，使行为与已测版本不符。编排层调用时不执行它，改跑只读的 `scripts/check_update.py`：同时查看退出码、stdout 与 stderr；即使退出码为 0，只要输出表明远程检查失败或降级本地，就记录“更新检查失败，继续使用已安装版本”，不能声称已是最新，也不把原因一律归为无网。有新版本时告知用户并记录，用户同意才更新。Windows 上把其命令中的 `python3` 换成 `python`。
- 其余按其当前入口的模板选择、制作及检查流程执行。先按场景、风格、主色筛选，再按 §四 展示候选。
- **模板页映射**：确认逐页大纲时一并列出“大纲页 → 模板页”一行映射；结构、块数装不下的页当场提出，不留到制作阶段。不删页、不删数据、不硬套无关版式。
- 映射前查看模板页渲染图；照片与本页内容无关就换页，gorden 不能替换图片，无法换页时说明差异请用户决定。
- 映射写明关键数字所在槽位；关键数据不得放小字说明槽，优先大字数字版式，没有则说明。
- 图标、图形含义必须与内容相符，不符就换页。
- 确认稿要求不出现未经验证的数据时，只选无示例数据的页面，不带着示例数据交付；不删除图形或遮盖数字。
- 同时更新图表数值与图形含义；装饰性百分比图不是原生图表。
- 输出为 `{项目目录}/{项目目录名}.pptx`。

### D. HTML 常规：html-ppt

- Skill：`{skill:html-ppt}/SKILL.md`。
- 主题选择：用户未指定时使用 html-ppt 自带默认主题，在需求表记录“按 html-ppt 默认主题”，不硬编码编排层主色，也不发明新色值；需要建议时从其现有主题中给 2–3 套供选。用户未修改即按记录执行，制作阶段不再二次追问。
- 用户已选主题或配色时原样保留，不静默替换其 token；确需覆盖主蓝时在项目内覆盖主题变量，并把最终配色写进需求记录；不直接修改制作 Skill 的共享 CSS 或模板资源。视觉密度为复杂豪华时采用更丰富的图示和信息组织，专业简洁时采用留白和精炼表达。
- 演讲、培训等需要讲者提示时，按其规范处理备注和演讲者视图。
- 输出为 `{项目目录}/{项目目录名}.html`。不要把 HTML 改名成 `.pptx`，也不要声称它是可编辑 PowerPoint。
- 可以内联资源形成单文件；如使用独立资源，应复制到项目 `assets/`，以相对路径引用，确保移走整个项目文件夹后仍可打开。
- 不把主题切换或模板默认色留成可覆盖确认配色的最终状态；预期断网放映时验证字体回退和本地资源。

### E. HTML 杂志风或设计感：guizang-ppt-skill

- Skill：`{skill:guizang-ppt-skill}/SKILL.md`。
- 判断风格意图：明确要求“杂志风”“杂志感”“瑞士风”或指定 guizang 即进入；只出现“设计感”时，先给用户一次 D/E 二选一（说明常规网页与杂志/瑞士风的差异）。“不要杂志风”“不需要设计感”、只是举例、只在素材或文档正文里出现这些词，以及只说“复杂豪华”“高级”“好看”“专业”都不触发。用户明确指定 html-ppt 时复用其选择，不被风格关键词覆盖；与格式/模板硬要求冲突则先解决冲突。
- 电子杂志 A 和瑞士风 B 只能选一种：明确要求“杂志风”记为 A，明确要求“瑞士风”记为 B，已明确的选择直接复用；用户在 D/E 确认中选择 E 后仍未明确 A/B 时，结合主题推荐并补问一次，不重新调研目标和听众。授权直出时，A/B 与主题由 AI 按需求表选定并记录，不再转问用户。
- 按 guizang 当前入口执行更新检查、模板和主题选择；该 Skill 的更新需要用户确认，拒绝或无法检查（如已锁定版本、无 upstream）时按其规则继续现有版本，不擅自改写安装文件。
- 采用其主题库，不继承 html-ppt 的默认主题。guizang 不直接使用用户给的色值：用户指定品牌色时，用其 `scripts/gz-theme.mjs` 生成受约束的品牌主题（需要 node）。脚本判定不达标或 node 不可用时，说明影响并请用户选择预设主题或改走 D，不静默换成预设色。交付时说明实际色值可能与原色值有差异。
- 正式演讲使用确认稿的页面目的、讲者要点、转场和稳定页面 ID；逐页讲述预算最多占可用演讲时长 90%，计入的问答/互动和缓冲单独列出。不得直接把每页原时长缩短后冒称仍是已确认内容。
- 图片/截图已有用途、比例及保真要求时直接复用；仅补问缺口。缺少必需素材时不能用未说明的占位图冒充成品。
- 大量表格或密集培训内容与该 Skill 的适用范围冲突时，指出具体页面的问题，询问调整表达还是更换路线，不为风格擅自删内容。
- 模板默认的 `项目/XXX/ppt/index.html` 仅是该 Skill 的示例位置；本次最终入口统一写到 `{项目目录}/{项目目录名}.html`。外置图片放同项目 `images/` 并同步相对路径，不另建第二套项目目录。
- 单文件 HTML 不等于离线无依赖；只有实际验证后才承诺离线放映。

### F. 现有 PPTX 修改/美化：ppt-master Edit Native / Generate（beautify-pptx profile）

- Skill：`{skill:ppt-master}/SKILL.md`。
- 仅处理入口③，输出固定为可编辑 PPTX；不重做叙事，不换输出格式。
- 源文件处理按 edit.md；成品写到 `{项目目录}/{项目目录名}.pptx` 或用户指定路径，绝不覆盖源文件；交付前后各核一次指纹。
- 保留原版式增量编辑：使用 ppt-master 的 Edit Native PPTX 路由，按确认的逐页修改清单改文字、补页、加备注/动画；未列入清单的页保持原样；增删/重排页必须在修改方案中列明并确认。
- 保留内容重新设计：使用 ppt-master Generate PPTX 的 `beautify-pptx` profile（不是独立路由），保持已确认的内容、页序、页数和结论，只改变视觉表达；需要改内容或页序时转入口②。
- 传入源 PPTX、`需求调研.md`、`修改方案_确认版.md` 和必须保留项；要求下游保留未列入清单的页面、文字、数据、品牌元素、页序和备注（Beautify 全量重设计时保留内容、页序、页数和数据）；修改页的文字必须可编辑。
- 无法保留必须保留项或源设计时，说明具体页码、差异、原因和影响，回到修改方案确认，或请用户在 Beautify、重做、改用其他 PPTX 编辑方式之间选择；不静默替换、删除或降级。

## 三、成品检查

先执行制作 Skill 要求的检查，再核对交付内容。失败后修复并重跑受影响检查。

制作工具的原始输出放在 `{项目目录}/_build/<skill 名>/` 内，标准成品路径为 `{项目目录}/{项目目录名}.pptx`，不得让原始输出占用标准路径。现成模板库构建后、交付前，若有孤儿部件，运行 `python "{SKILL_DIR}/scripts/clean_deck.py" "{项目目录}/_build/<skill 名>/<原始输出.pptx>" --out "{项目目录}/{项目目录名}.pptx"`；没有孤儿时直接复制原始输出到标准路径。其他分支同样处理；不改依赖安装文件，以下 verify 和逐页视觉检查均使用标准路径上的最终成品。

**结构检查（交付前必跑）**：

```text
python "{SKILL_DIR}/scripts/verify_deck.py" {成品路径} --expected-pages {确认稿页数} --brief
```

有 FAIL 不得报告完成。WARN 要处理或在交付摘要说明；其中“未显示的幻灯片部件”表示模板页仍藏在文件里，须清理。它只查结构，**不能替代视觉检查**。

不因检查工具缺失就宣称通过。

共同检查：

- 页数、页序、标题、结论、数据与确认稿一致（执行记录中已登记的交付后微调除外），章节及目录对应。
- 真实数据、单位、统计日期和引用准确，无未经说明的编造、示例数据或遗漏。
- 没有模板示例文字、失效素材、意外占位符；需要用户补齐的关键内容尚未解决时，不标成最终成品。
- 字体、主色、页面层级一致；无明显文字溢出、遮挡和裁剪错误。

内容适配（看渲染结果逐页核对，关键词扫描查不出这些问题）：
- **不为填满模板凑内容**：在大纲与模板页映射时就核对真实内容能否填满所选并列块；不足时先换用块数匹配的页面。仍无法承载时说明具体缺口，请用户补材料或确认调整；不擅改已确认页数、模板或内容范围。授权直出可在已授权的设计选择内选页，但仍不得编造事实或用空话填块。
- “用户提供年度汇总测试数据”“未提供原因分析，不作无依据归因”等制作过程说明放在执行记录或交付限制中，不为填块写进面向听众的正文。听众确实需要的统计口径、来源、风险与不确定性说明应保留；用户要求展示的数据局限或方法说明也可上页。按信息对听众的作用判断，不靠禁词删除。
- 核对照片相关性、关键数字的大字槽位和图标/图形含义；不符时按模板页映射要求换页或说明差异。

- 标题里的数量词与图形块数一致（反例：标题“四位一体”，图形却是 5 块）。
- 模板每个并列块都有独立且切题的内容；不复用同一段，不张冠李戴。
- 每页只传达一个主结论；渲染后标题不异常折行，不残留无意义的装饰数字。
